# Migration to Java / Spring Boot

The backend has been migrated because the owner/developer is more comfortable maintaining Java. The existing interface, API routes and workflows were retained. Runtime Node.js, Express and native npm SQLite dependencies were removed. Node remains optional for browser tests and exporting the historical mockup.

## Stack

- Java 21 LTS; Spring Boot 3.5.16 (the latest 3.5 patch published in Maven metadata when selected).
- Spring Security for the filter chain and password primitives, plus the existing table-backed session/CSRF contract.
- Spring JDBC and explicit transactions with Xerial SQLite JDBC.
- Java HTTP client for Gmail/WhatsApp, Spring scheduling for durable database jobs, AWS SDK for Java v2 for S3.
- Maven Wrapper pinned to Maven 3.9.9 with a verified distribution checksum.

No RDS or Redis was added. The one-instance Canada Central deployment and indicative infrastructure allowance remain unchanged. Java can use more memory than the former Node process; the planned small 2 GB instance still needs monitoring under the actual pilot workload. No paid framework licence is required.

## Existing data

The SQLite table layout/schema version remains compatible with the previous implementation. Reuse the same DB_PATH and DATA_KEY; never initialize a new key over an existing encrypted installation. The application validates the schema version on startup.

- Existing contacts, leads, policies, conversations, requests, settings, jobs, audit records and session hashes are retained.
- Legacy Node scrypt password hashes are verified using the same parameters and ASCII-encoded salt representation. After successful login they are upgraded to a SHA-256-prehashed BCrypt format so long UTF-8 passwords are handled consistently.
- AES-256-GCM stored-token and backup envelopes keep the previous `iv:tag:ciphertext` hex format. Compatibility tests use fixtures generated by Node's actual crypto implementation.
- Existing authenticator seeds and counters are retained. APP_ENV is the preferred environment name; NODE_ENV remains a compatibility fallback for an existing `.env`.
- Millisecond UTC timestamps and the existing API response field names are retained.

## Safe upgrade procedure

1. Take a consistent encrypted backup before stopping the old application. Preserve DATA_KEY and MFA recovery information independently.
2. Stop the old application completely. Do not run the two runtimes or multiple replicas against the same database concurrently.
3. Deploy the Java release with the same database volume, key, production URL and authenticator seed. Use the Java Docker image/entrypoint; do not copy over the database.
4. Initially set MESSAGING_MODE=mock, or keep ALLOW_LIVE_SENDS=false for live connection checks. Verify the existing owner sign-in, record counts, policy dates, stored integrations and job history.
5. Inspect any queued/running sends against provider history before enabling delivery. Ambiguous sends remain held for review; never blindly replay them.
6. Complete supervised provider and backup/restore acceptance checks before returning to normal operation.

Rollback must restore a **pre-migration database snapshot**, not merely switch the executable. The old Node runtime cannot verify passwords after Java upgrades them to the new hash format. Keep live sending disabled during recovery/reconciliation. No real client installation was migrated during development; preservation was verified with controlled database/crypto fixtures and compatibility tests.

## Development and operations

Use `./mvnw verify` and `java -jar target/mapledesk-1.0.0.jar`. Import pom.xml directly into IntelliJ or another Java IDE. Main code is under `src/main/java/com/mapledesk`, tests under `src/test/java`, and browser resources under `src/main/resources/static`.

Commands replacing the Node scripts:

| Operation | Java command after packaging |
|---|---|
| Initial owner | `java -jar target/mapledesk-1.0.0.jar --app.command=init` |
| Reset owner / revoke sessions | `java -jar target/mapledesk-1.0.0.jar --app.command=reset-owner` |
| Encrypted S3 backup | `java -jar target/mapledesk-1.0.0.jar --app.command=backup` |
| Restore to a new path | `java -jar target/mapledesk-1.0.0.jar --app.command=restore --source=backup.enc --destination=NEW-DATABASE-PATH` |

Set owner credentials and encryption/provider values privately in the environment or protected `.env`; no secret is passed as a command-line argument above. Restore does not start the web server or initialize the live database. See DEPLOYMENT.md for production configuration and recovery steps.
